# YackBang (약방) — 기획 문서 (PRD)

> 약방의 감초처럼, 꼭 필요한 순간에 찾게 되는 의약품 병용 정보 서비스

---

## 1. 프로젝트 개요

### 배경

약을 두 가지 이상 복용할 때 "같이 먹어도 되나?" 라는 의문은 매우 흔하다.  
전문가용 DUR(Drug Utilization Review) 시스템은 존재하지만, 일반 사용자가 접근하기에는 용어가 어렵고 인터페이스가 불친절하다.  
YackBang은 이 정보를 누구나 쉽게 확인할 수 있도록 풀어서 전달하는 것을 목표로 한다.

### 핵심 가치

- **쉬운 언어** — 전문용어 없이, 누구나 이해할 수 있는 한국어로 결과 표현
- **빠른 확인** — 검색부터 결과까지 최대 3단계 이내
- **신뢰할 수 있는 데이터** — 식품의약품안전처 공식 데이터 사용

---

## 2. 타겟 사용자

| 사용자 유형 | 상황 예시 |
|---|---|
| 일반 성인 | 감기약이랑 소화제 같이 먹어도 되나요? |
| 만성질환자 | 혈압약 복용 중 타이레놀 먹어도 되나요? |
| 보호자 | 어르신이 드시는 약들이 서로 괜찮은지 확인하고 싶어요 |

**타겟 아님:** 의사, 약사 등 전문가 (전용 시스템이 이미 존재)

## 3. 핵심 기능

### 3-1. 약품 검색

#### 약 이름의 두 가지 층

사용자가 아는 약 이름과 식약처 등록 이름은 다르다.

| 구분 | 예시 | 사용자 인지도 |
|---|---|---|
| 제품명 (박스에 적힌 이름) | 타이레놀, 게보린, 판피린 | 높음 — 대부분 이걸로 알고 있음 |
| 식약처 품목명 | 타이레놀정500mg(아세트아미노펜) | 낮음 — 잘 모름 |
| 성분명/일반명 | 아세트아미노펜, 이부프로펜 | 중간 — 아는 사람만 앎 |

> 병용금기는 **성분 기준**으로 판단된다. 제품명이 달라도 같은 성분이면 동일하게 적용.

#### 검색 동작

- 제품명(박스 이름) 기준 부분 검색 — "타이레놀" 입력 시 "타이레놀정500mg" 등 매칭
- 성분명 입력도 지원 — "아세트아미노펜" 입력 시 해당 성분 포함 제품 전체 표시
- 자동완성 항목에 제품명 + 성분명을 함께 표시 — 같은 성분의 다른 제품임을 인지할 수 있도록

```
입력: "타이레놀"

자동완성:
  [이미지]  타이레놀정500mg          성분: 아세트아미노펜
  [이미지]  타이레놀이알서방정650mg  성분: 아세트아미노펜
  [이미지]  타이레놀8시간이알서방정  성분: 아세트아미노펜
```

- 선택된 약은 칩(chip) 형태로 목록에 추가, 최대 5개
- 칩에도 미니 이미지 + 제품명 + 성분명 함께 표시

#### 약품 이미지

사용자가 약을 시각적으로 확인할 수 있도록 이미지를 함께 표시한다.

**이미지 우선순위:**

1. **포장(박스) 이미지** — 사용자가 가장 익숙한 형태, 크롤링으로 수집
2. **낱알 이미지** — 식약처 API 제공, 약국에서 받은 알약 식별에도 유용
3. **Fallback** — 이미지가 없는 경우 약 모양 아이콘(💊)으로 대체

포장 이미지와 낱알 이미지가 둘 다 있으면 나란히 표시한다.

| 표시 위치 | 표시 방식 |
|---|---|
| 자동완성 드롭다운 | 좌측 썸네일 (32×32px) |
| 선택된 약 칩 | 칩 왼쪽 미니 이미지 |
| 결과 카드 | 약품명 옆 이미지 (64×64px 내외) |

---

### 3-2. 검색 모드 — 단일 / 병용 자동 분기

선택한 약 개수에 따라 모드가 자동으로 결정된다.

#### 단일 모드 (약 1개)

- 해당 약의 기본 정보 (효능, 주의사항)
- 임부 금기 / 고령자 주의 뱃지 표시
- **이 약과 함께 먹으면 안 되는 약 목록** — 위험도 높은 순 정렬, 상위 5건 노출 후 "더 보기"
  - 각 항목: 금지 약품명 + 한 줄 요약 (쉬운 말)
- "이 약 추가해서 병용 확인하기" 버튼 — 병용 모드로 자연스럽게 전환

#### 병용 확인 모드 (약 2~5개)

- **기준 약** = 첫 번째로 추가한 약 (시각적으로 강조 표시)
- 기준 약과 나머지 각각 1:1 비교
- 결과는 3단계 등급으로 표시

| 등급 | 의미 |
|---|---|
| 🔴 위험 | 함께 복용하면 안 돼요 |
| 🟡 주의 | 복용 전 의사/약사에게 먼저 확인하세요 |
| 🟢 안전 | 병용 금기 정보가 없어요 |

> **최대 5개 제한:** 5개 초과 복약은 의료진이 직접 관리하는 영역. 5개 선택 시 추가 버튼 비활성화.

### 3-3. 결과 화면 언어 원칙

#### 허용 표현

| 유형 | 예시 |
|---|---|
| 병명 | 고혈압, 당뇨, 심부전, 간질환 |
| 부작용명 | 어지러움, 구역질, 출혈, 심박수 증가, 혈압 상승 |
| 일반 서술 | ~할 수 있어요, ~위험이 있어요, ~주의가 필요해요 |

#### 금지 표현

| 유형 | 예시 |
|---|---|
| 약리 메커니즘 | CYP3A4 억제, QT 연장, 항콜린 작용 |
| 의학 약어 | AUC 증가, Cmax, t½ |
| 전문 의학 용어 | 세로토닌 증후군, 신독성, 횡문근융해증 → 증상 중심으로 풀어서 표현 |

> 예시: "세로토닌 증후군 위험" → "뇌에 특정 물질이 과도하게 쌓여 경련, 발열이 생길 수 있어요"

#### 면책조항

모든 결과 화면에 닫을 수 없는 형태로 항상 고정 표시한다.

> 이 정보는 참고용이며, 실제 복약 전에는 **반드시 의사 또는 약사와 상담**하세요.  
> YackBang은 의료 서비스가 아니며, 제공된 정보에 대한 의학적 책임을 지지 않습니다.

- 위치: 페이지 하단 sticky footer
- 스타일: 회색 계열 소형 텍스트, 결과를 가리지 않도록

## 4. 사용자 플로우

### 단일 조회

```
약 이름 검색 → 자동완성 선택 (1개)
    ↓
[결과 — 단일 모드]
 ├─ 약 기본 정보 + 이미지 (포장 / 낱알)
 ├─ 임부 금기 / 고령자 주의 뱃지
 └─ 함께 먹으면 안 되는 약 목록 (위험도 순)
      각 항목 → "이 약 추가해서 확인하기" 버튼
```

### 병용 확인

```
첫 번째 약 검색 → 선택 (기준 약)
    ↓
추가 약 검색 → 선택 (2~5개까지 반복)
    ↓
"병용 확인하기" 버튼
    ↓
[결과 — 병용 모드]
 기준약 vs 약B  →  🔴 위험  (카드 펼치면 쉬운 말 설명)
 기준약 vs 약C  →  🟢 안전
 기준약 vs 약D  →  🟡 주의  (카드 펼치면 쉬운 말 설명)
```

## 5. 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| 프레임워크 | Next.js 16 (App Router) | API Route로 백엔드 통합, Vercel 배포 최적 |
| 언어 | TypeScript | 타입 안정성 |
| 스타일 | Tailwind CSS v4 + shadcn/ui | 빠른 UI 구성, 일관된 디자인 |
| HTTP | axios | 식약처 API 호출 |
| DB | Supabase (PostgreSQL) | DUR 전체 데이터 저장 및 성분명 검색 |
| 캐싱 | Next.js `unstable_cache` | 서버 레벨 캐싱, 요청 간 공유 |
| AI 변환 | Claude Haiku (Anthropic API) | 전문용어 → 쉬운 말 변환 |
| 배포 | Vercel | Next.js 궁합, 무료 플랜으로 포트폴리오 운영 |

> DuckDB 도입 여부는 실제 API 응답 데이터 확인 후 결정한다. 여러 엔드포인트 결과를 복합 JOIN해야 할 경우에만 도입 검토.

## 7. 데이터 처리 전략

### 핵심 문제

식약처 DUR API 원문은 전문용어로 작성되어 있어 일반 사용자가 이해하기 어렵다.  
이를 쉬운 말로 변환하는 것이 이 서비스의 핵심 가치이자 기술적 과제다.

### 3단계 처리 흐름

#### 1단계 — 규칙 기반 용어 치환

자주 등장하는 전문용어를 미리 정의한 매핑 테이블로 빠르게 처리한다.

| 원문 (전문용어) | 치환 결과 |
|---|---|
| CYP3A4 억제 | 약 성분이 몸에서 더 오래 남아 |
| QT 연장 | 심장 박동이 불규칙해질 수 있어 |
| 혈중농도 증가 | 약 성분이 혈액에 더 많이 쌓여 |
| 신독성 | 신장(콩팥)에 무리를 줄 수 있어 |
| 횡문근융해증 | 근육이 손상되는 심각한 부작용이 생길 수 있어 |

> 실제 매핑 항목은 API 실물 데이터 확인 후 확정한다.

#### 2단계 — Claude Haiku AI 변환

1차 치환 후 전체 문장을 자연스러운 한국어로 재구성한다.

**프롬프트 원칙:**
- 병명 / 부작용명은 그대로 유지
- 약리 메커니즘 설명은 증상 중심으로 변환
- 중학생도 이해할 수 있는 수준의 한국어
- 1~2문장 이내로 압축

#### 3단계 — 캐싱으로 AI 호출 최소화

병용금기 데이터는 자주 바뀌지 않는다. 한 번 변환한 결과를 캐시에 저장해두면 같은 약 조합에 대해 AI를 다시 호출하지 않아도 된다.

| 항목 | 내용 |
|---|---|
| 캐시 키 | 약품 ID 조합 (예: `198500077_200904427`) |
| TTL — 병용금기 결과 | 7일 |
| TTL — 이미지 URL | 30일 |
| 캐시 방식 | Next.js `unstable_cache` |
| AI 호출 시점 | 캐시 MISS일 때만 |

## 8. 데이터 소스

### 식약처 공공데이터 API (data.go.kr)

실물 테스트로 확인된 API만 기재한다. 세부 명세는 `docs/API.md` 참고.

| 서비스 | 엔드포인트 | 용도 | 검색 파라미터 |
|---|---|---|---|
| 의약품 허가정보 | `DrugPrdtPrmsnInfoService07` | 제품명 검색, 박스 이미지 | `item_name` |
| 낱알 이미지 | `MdcinGrnIdntfcInfoService03` | 낱알 사진 URL | `item_name` |
| DUR 병용금기 | `DURPrdlstInfoService03` | 병용금기 데이터 (전체) | 필터 불가 |
| DUR 임부금기 | `DURPrdlstInfoService03` | 임부금기 데이터 (전체) | 필터 불가 |

- 인증 방식: 공공데이터포털 서비스키 (`serviceKey` 쿼리 파라미터)
- ⚠️ 검색 파라미터명: `item_name` (언더스코어) — `itemName` 아님
- 요청 제한: 1일 10,000건 (공통)

### 포장(박스) 이미지

허가정보 API의 `BIG_PRDT_IMG_URL` 필드로 직접 제공된다.  
단, 모든 약품에 이미지가 있지 않으므로 없을 경우 낱알 이미지 → 아이콘 순서로 fallback.  
**크롤링 불필요** (당초 계획 변경).

### DUR 데이터 처리 방식

DUR API는 텍스트 필터링이 불가능(실물 테스트 확인)하므로,  
전체 데이터를 **Supabase(PostgreSQL)에 임포트하여 SQL 쿼리**로 처리한다.

- 데이터 출처: data.go.kr "의약품안전사용서비스(DUR) 의약품 목록" 파일데이터
- 병용금기 총 811,620건 / 임부금기 총 16,093건
- Supabase 무료 플랜 500MB 내 수용 가능
- 갱신 주기: 월 1회 수동 업데이트 (DUR 데이터는 자주 바뀌지 않음)

## 9. UI/UX

### 디자인 원칙

- **미니멀** — 필요한 정보만, 깔끔하게
- **명확한 피드백** — 로딩, 에러, 결과 각 상태를 명확히 표시
- **PC / 모바일 듀얼 레이아웃** — 동일한 UX 흐름, 화면 크기에 따라 배치 전환

### 페이지 구성

| 페이지 | 경로 | 설명 |
|---|---|---|
| 메인 | `/` | 검색 + 결과를 한 페이지에서 처리 |
| 약품 상세 | `/drug/[id]` | 단일 약품 직접 링크 / 공유용 |

결과는 별도 페이지 이동 없이 메인 페이지 내에서 표시한다.

## 11. 제약 및 고려사항

- **의학적 책임 없음** — 서비스는 정보 제공 목적, 면책조항 필수 표시
- **API 요청 한도** — 1일 10,000건, 캐싱으로 실질적 호출 최소화
- **크롤링 윤리** — 공공 기관 사이트 대상, robots.txt 준수, 과도한 요청 금지
- **이미지 수급** — 포장/낱알 이미지 모두 없는 약품 존재 가능, 아이콘 fallback 처리 필수
- **데이터 최신성** — 식약처 API가 공식 최신 데이터, 별도 동기화 불필요
